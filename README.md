# Adaptive construction of parametric deep learning aided surrogates for convection-diffusion-reaction processes

This repository contains the code and results of the paper.

The paper proposes two parametric surrogates for singularly perturbed boundary value problems:

- **PA-DNN**, the parameter-adaptive deep neural network.
- **PGA-DNN**, the parameter-geometry-adaptive deep neural network.

Both networks take `(x, eps)` as input. They are trained on labels computed with the implicit-explicit local differential transform method (IELDTM).

Training adds new labels in adaptive steps:

- The residual of the governing equation selects the perturbation parameter `eps*` for which new labels are generated.
- PGA-DNN also builds a residual-guided nonuniform mesh, on which the IELDTM computes these labels.

## Test problems

| | Equation | Boundary conditions | Training range |
|---|---|---|---|
| TP1 | `-eps u'' - 2u' = 0` | `u(0) = 1, u(1) = 0` | `eps in [4e-4, 1]` |
| TP2 | `-eps u'' + 2(2x - 1)u' + 4u = 0` | `u(0) = 1, u(1) = 1` | `eps in [7e-4, 1]` |
| TP3 | `-eps u'' + u(1 + u) = exp(-2x/sqrt(eps))` | `u(0) = 1, u(1) = exp(-1/sqrt(eps))` | `eps in [1e-5, 1]` |

## Installation

```
pip install -r requirements.txt
```

The results were obtained with Python 3.13.15, PyTorch 2.14.1 (CPU) and NumPy 2.5.4.

## Usage

Use `train.py` to train a model:

```
python src/train.py --problem TP1 --method PGA --seed 1234
```

| Option | Values |
|---|---|
| `--problem` | `TP1`, `TP2`, `TP3` |
| `--method` | `PGA` (PGA-DNN), `PA` (PA-DNN), `DD` (data-driven DNN on fixed data), `PINN` (parametric PINN) |
| `--seed` | random seed (paper: 1234, 2468, 4123, 5678) |
| `--na` | number of uniform points per adaptive step of PA-DNN (default: value of the paper) |

The results are written to `results/<problem>/<method>/seed<seed>/`. To regenerate the tables and figures from the stored models, run the scripts in `scripts/`, for example:

```
cd scripts
python table1.py
```

`run_all.sh` trains all models of the paper and then regenerates every table and figure.

On a CPU, a PGA-DNN, PA-DNN or DD run takes about 20-25 minutes, and a PINN run takes 1-2 hours.

## Settings

All models use the following settings:

- **Network:** 3 hidden layers of 60 neurons, tanh activation, Xavier normal weights and zero biases.
- **Optimizer:** Adam, full batch, learning rate `1e-3`. For TP2 the learning rate is reduced to `1e-4` after 30000 iterations and to `1e-5` after 70000 iterations.
- **Iterations:** `k_max = 100000` with no early stopping; the final model is evaluated.
- **Pre-training:** the first `A = 10000` iterations use the initial labelled data: 500 uniform points for 10 values of `eps`.
- **Adaptive steps:** one step every `k = 1000` iterations, i.e. 90 steps.
- **Selection of `eps*`:** at every step, 100 log-uniform values of `eps` and 100 random `x` per value are drawn. `eps*` is the value with the largest mean squared residual.

The methods differ as follows:

| Method | Labels | TP1 | TP2 | TP3 |
|---|---|---|---|---|
| PGA-DNN | nonuniform mesh, `Na` uniform + `M` adaptive points per step | `Na = M = 100` | `Na = M = 100` | `Na = M = 50` |
| PA-DNN | uniform mesh, `Na` points per step | `Na = 500` (Table 2: `Na = 200`) | `Na = 200` | `Na = 100` |
| DD | fixed data: initial data + 90 log-uniform `eps` values on uniform meshes | 200 points | 200 points | 100 points |
| PINN | no labels; loss = PDE residual + boundary conditions (equal weights) | `N_f = 10^4` collocation points, 50 boundary points, `eps` log-uniform | | |

### Error measures

The errors are computed with respect to the exact solution on a test grid. The grid has 1001 uniform points plus 401 points in each boundary layer region: `[0, 20 eps]` for TP1, both ends for TP2, and `[0, 20 sqrt(eps)]` for TP3.

- `||E||_inf` is the maximum absolute error.
- `||E||_2` is the L2 error, computed with the trapezoidal rule.

## Notes

- **Timings.** `timings.csv` is provided only for the two runs of Table 2 (TP1, seed 1234, PGA-DNN and PA-DNN with `Na = 200`), which were executed one at a time. The other runs were executed in parallel, so their wall-clock times are not comparable. The column `offline_time_s` of their `convergence_history.csv` should therefore not be used for cost comparisons.
- **Not included.** Figs. 4 and 5 of the paper (the architecture study and the IELDTM solutions plotted with MATLAB) are not part of this repository.
